# Project instructions

- Target Android. Use the cloned `Android-port/` tree as a read-only reference. Read [HANDOFF.md](HANDOFF.md) and [AUDIT.md](AUDIT.md) for project scope and checked revisions.
- For hardware-dependent bugs, help the hardware owner prepare and submit their own PR. Start with the shortest receive-only reproduction and the minimum evidence needed to isolate the failing layer. Point to [CONTRIBUTING.md](CONTRIBUTING.md) and give copyable commands where they exist. Help the owner create a branch, patch, build, test and draft the PR. Ask the owner to run checks that need their physical setup and keep software-only results distinct from owner-reported results.
- Route a confirmed Hamlib backend, CAT protocol or rigctld defect to [upstream Hamlib](https://github.com/Hamlib/Hamlib). Help the owner reproduce against a named upstream revision and prepare the upstream PR or issue. If ownership is still unclear, compare the same rig/model/settings on stock Hamlib where practical and inspect the Android bridge evidence. Treat inability to reproduce on another transport as inconclusive when it exercises a different path. Keep Android permission, bridge, routing, packaging and lifecycle fixes here. Use linked PRs for separate changes when both layers are involved.
- Keep hardware fixes small and reproducible. Use a sanitized failing transcript or a fake transport regression test where it captures the fault. Include the affected revisions, expected and observed behavior, exact verification steps and remaining gaps. Ask before publishing or contacting upstream on the owner's behalf.
- Preserve the self-service workflow in human-facing docs. When introducing or changing hardware-facing paths, update the relevant build, diagnostic and verification instructions in the same change so another owner can reproduce the result without maintainer access to their equipment.
- Keep reproducers receive-only by default. Real PTT/TX checks require deliberate owner consent and a low-power dummy-load setup. Never claim a physical check ran without evidence.
- Use the [hardware matrix](HANDOFF.md#hardware-and-android-coverage) when requesting owner verification. The owner has a Pixel 8a, an FX-4CR and a (tr)uSDX. Seek contributor results for other phones and rigs, especially the proposed Android version floor, before listing those combinations as verified.
